## 0. CANONICAL PARAMETER DISCIPLINE (hard)

All analysis commands in this appendix carry canonical parameter sets
derived from Praat GUI defaults or published clinical norms. These
values are the standard for all PraatGen-generated scripts.

**Deviation policy:** A parameter may be changed from its canonical
value ONLY when the canonical value would cause the algorithm to
miss, clip, or mischaracterize signal that is demonstrably present
in the data. The justification must identify:

1. Which signal would be missed (e.g., "F0 at 65 Hz falls below
   the 75 Hz floor — the algorithm cannot detect periods longer
   than 1/floor")
2. Why the canonical value fails for this specific data

The following are NOT valid justifications for deviation:
- "Provides extra headroom" / "doesn't hurt"
- "The canonical ceiling exceeds what's needed, so I lowered it"
- "Wider range gives better coverage"
- "The singer might occasionally go below X"
- "It's closer to the expected range" (without signal-loss evidence)

Narrowing a range below canonical is just as much a deviation as
widening it. A ceiling of 500 Hz when canonical is 600 Hz requires
the same justification as a floor of 50 Hz when canonical is 75 Hz.

**PRE-FLIGHT obligation:** When the task involves singing or
non-speech phonation, ask whether the expected range extends beyond
the canonical detection window (below floor or above ceiling/top).
If the user does not confirm that it does, use canonical values.
Do not preemptively adjust.

**Interaction with the 2× pitch top rule (§1A):** The filtered
autocorrelation algorithm's LPF creates a genuine signal-loss
scenario: if the singer's highest expected F0 exceeds pitch_top / 2,
the algorithm attenuates real pitch energy before analysis. In that
case, raising pitch_top to 2× the highest expected F0 is a valid
deviation because the canonical value would miss signal. If the
highest expected F0 does NOT exceed pitch_top / 2 (i.e., canonical
800 / 2 = 400 Hz covers the range), canonical stands.

**SELF-AUDIT requirement:** Every deviation from canonical must cite
this rule and state the signal-loss evidence:

    "Deviation from canonical [parameter] = [value] because
    [signal at X Hz would be missed by canonical Y Hz]."

If no deviations exist, state: "All parameters canonical per §0."

# raw autocorrelation defaults. Do NOT copy parameters between algorithms.
#
# Always solicit the expected pitch range from the user before selecting

### 3D. Variant selection (hard)

# Jitter and shimmer each have several variants. They are NOT
# interchangeable, and the difference is large enough to invert a
# clinical reading. Do not pick one silently.
#
# CLARIFICATION (Step 1B hook) — ONE question, not two:
#   "What is the phonation task? Sustained vowel / sustained with
#    vibrato / pitch-varying (glide, scale, register transition) /
#    connected speech."
# Task type governs which variants are VALID at all (matrix below), so it
# is the question that must be asked. Do NOT also present the variant list
# as a menu — emit local, rap and the ratio by default (see below) and the
# data answers the variant question. Offer a specific variant only if the
# user asks or a protocol names one. Never explain what jitter is; anyone
# requesting it has a working definition.
#
# ---------------------------------------------------------------------
# VARIANTS  (arity verified, Praat 6.6.30, 29 Jul 2026)
#
# Jitter — PointProcess selected, 5 arguments:
#   Get jitter (local):            0, 0, 0.0001, 0.02, 1.3
#   Get jitter (local, absolute):  0, 0, 0.0001, 0.02, 1.3    [seconds]
#   Get jitter (rap):              0, 0, 0.0001, 0.02, 1.3
#   Get jitter (ppq5):             0, 0, 0.0001, 0.02, 1.3
#   Get jitter (ddp):              0, 0, 0.0001, 0.02, 1.3
#
# Shimmer — PointProcess + Sound selected, 6 arguments:
#   Get shimmer (local):     0, 0, 0.0001, 0.02, 1.3, 1.6
#   Get shimmer (local_dB):  0, 0, 0.0001, 0.02, 1.3, 1.6     [dB]
#   Get shimmer (apq3):      0, 0, 0.0001, 0.02, 1.3, 1.6
#   Get shimmer (apq5):      0, 0, 0.0001, 0.02, 1.3, 1.6
#   Get shimmer (apq11):     0, 0, 0.0001, 0.02, 1.3, 1.6
#   Get shimmer (dda):       0, 0, 0.0001, 0.02, 1.3, 1.6
#
#   local        raw first difference between CONSECUTIVE periods or
#                amplitudes, over the mean. Absorbs any smooth modulation
#                of F0 or amplitude.
#   rap / apq3   deviation from a 3-point running mean.
#   ppq5 / apq5  deviation from a 5-point running mean.
#   apq11        11-point; heaviest smoothing.
#   ddp / dda    REDUNDANT. Both verified exactly 3x their base measure
#                in Praat 6.6.30 (ddp/rap = 3.000000, dda/apq3 = 3.000000,
#                sandbox, 29 Jul 2026), and the Praat manual states both
#                identities outright ("The value is three times RAP" /
#                "three times APQ3"). They carry no information rap and
#                apq3 do not. Do not report both.
#
# ---------------------------------------------------------------------
# THE CRITICAL PROPERTY
#
# `local` is a first difference, so it is sensitive to smooth F0 or
# amplitude modulation in proportion to (extent x RATE). `rap` and `ppq5`
# are effectively second-difference measures and reject smooth modulation
# almost entirely.
#
# Consequence: on a sustained tone WITH VIBRATO, `local` measures the
# vibrato, not phonatory stability. Monte Carlo, 8000 cycles, F0 244 Hz,
# underlying perturbation sigma 0.18%:
#
#   modulation             local%    rap%   local/rap
#   none                   0.2023  0.1170     1.730
#   2 Hz   +/-0.5 st       0.2198  0.1175     1.870
#   5.5 Hz +/-0.25 st      0.2346  0.1179     1.990
#   5.5 Hz +/-0.5 st       0.3157  0.1171     2.694
#   5.5 Hz +/-1.0 st       0.5472  0.1183     4.625
#   12 Hz  +/-0.5 st       0.5890  0.1279     4.606
#
# `rap` is invariant (0.117-0.128) across every condition; `local` varies
# by ~2.9x. A SLOW glide barely moves the ratio — rate drives this, not
# F0 excursion alone.
#
# ---------------------------------------------------------------------
# DIAGNOSTIC RATIO — emit local, rap and local/rap by DEFAULT
#
# For purely uncorrelated cycle-to-cycle perturbation, local/rap = sqrt(3)
# = 1.7321. Derivable analytically (local -> 2s/sqrt(pi);
# rap -> 2s/sqrt(3pi)) and confirmed by Monte Carlo at N = 400,000 for
# sigma = 0.2%, 0.5%, 1.0% (1.7302, 1.7314, 1.7327).
#
#   ratio ~1.73        clean; `local` is a valid stability measure
#   ratio > ~2.2       smooth modulation present (vibrato, tremor).
#                      Report rap or ppq5, and say why.
#   ratio -> 1.5       period-alternating structure (diplophonia,
#                      subharmonics). Investigate before reporting any
#                      perturbation value.
#
# 1.5 IS A FLOOR, NOT A THRESHOLD (correction, verified). Pure period
# alternation gives local/rap = 1.5000 EXACTLY, independent of alternation
# depth (Monte Carlo, N = 200,000, d = 0.2% and 1.0%: both 1.5000).
# Analytically: with e_i = -e_(i+1), the rap numerator is 4|e_i|/3 against
# a local numerator of 2|e_i|. So mixtures of alternation and noise fall
# BETWEEN 1.5 and 1.732, and a test written as "ratio < 1.5" can never
# fire. Test for approach to 1.5, not for falling below it.
#
# THE RATIO NEEDS CYCLES. It is an asymptotic expectation and scatters on
# short samples. Measured 95% spread on clean uncorrelated data:
#
#   N cycles     95% of ratios fall within
#      100         1.64 - 1.86
#      200         1.66 - 1.80
#      500         1.69 - 1.78
#     2000         1.71 - 1.76
#     8000         1.72 - 1.75
#
# The >2.2 flag is safe at any of these. The approach-to-1.5 flag is NOT
# reliable below ~500 cycles, where clean data alone reaches 1.64. State
# the cycle count whenever the ratio is reported, and do not call
# diplophonia on a short sample.
#
# ---------------------------------------------------------------------
# TASK APPROPRIATENESS MATRIX
#
#   Sustained vowel, steady pitch and loudness
#       All variants valid. `local` is the conventional clinical report.
#
#   Sustained vowel WITH VIBRATO  (most trained singers)
#       `local` is inflated by the vibrato and is NOT a stability measure.
#       Use rap/ppq5 (jitter) and apq3/apq5 (shimmer). Report vibrato rate
#       and extent alongside.
#
#   Pitch-varying (glide, scale, portamento, register transition)
#       Slow movement does not inflate `local` much, but this is not a
#       stability paradigm. Segment into steady portions and measure per
#       segment; a whole-file mean averages across registers. Same for
#       shimmer under a crescendo.
#
#   Connected speech
#       Perturbation measures are NOT valid. Use CPPS, or AVQI per §10.
#       Do not report jitter/shimmer on running speech.
#
# ---------------------------------------------------------------------
# RUNTIME GUARD (recommended). Both come free from the Pitch object the
# script already builds — no extra analysis object:
#   - F0 range in semitones over the analysis window; if > ~2 st, warn
#     that the window is not steady-pitch.
#   - Emit local, rap, the ratio and the cycle count; warn above ~2.2 that
#     a smooth modulation is inflating `local`.
#
# ---------------------------------------------------------------------
# CROSS-PROGRAM COMPARABILITY — PRAAT VALUES ARE NOT MDVP VALUES (hard)
#
# Praat manual, "Voice 5. Comparison with other programs":
#   https://www.fon.hum.uva.nl/praat/manual/Voice_5__Comparison_with_other_programs.html
# Variant definitions and the MDVP thresholds below:
#   https://www.fon.hum.uva.nl/praat/manual/Voice_2__Jitter.html
#   https://www.fon.hum.uva.nl/praat/manual/Voice_3__Shimmer.html
#
# Give the user the URL, or this summary, whenever a jitter or shimmer
# number will be compared against a clinical threshold or against a value
# from other software. Most published norms come from MDVP.
#
# THE MEASURES ARE NOT THE SAME QUANTITY. Boersma's worked case: a
# computer-generated glottal source with a CONSTANT period, vocal-tract
# filtered, plus 1% additive white noise ("a quite usual amount") —
#
#     Praat measures jitter 0.02%      MDVP measures jitter 0.6%
#
# True jitter is zero. The 30x gap is method, not implementation quality:
#   Praat  — period boundaries by waveform matching (cross-correlation),
#            which averages the noise out
#   MDVP   — period boundaries by peak-picking, which follows the noise
# So MDVP's "jitter" conflates period variation with additive noise;
# Praat's isolates period variation. On clean synthetic signals both
# recover 1% jitter, so the divergence is a NOISE effect and grows with
# recording quality problems.
#
# Voicing decisions also differ, which changes which cycles are measured
# at all: MDVP quantizes amplitudes to -1/0/+1 before autocorrelation,
# does not divide by the window's autocorrelation, and does not
# sinc-interpolate the peak. Praat's voicing threshold is 0.45 against
# MDVP's 0.29 — MDVP calls more frames voiced.
#
# MDVP PATHOLOGY THRESHOLDS, AND WHY THEY DO NOT TRANSFER (hard).
# The Praat manual reproduces MDVP's thresholds:
#
#   Jitter (local)              1.040 %
#   Jitter (local, absolute)   83.200 us
#   Jitter (rap)                0.680 %
#   Jitter (ppq5)               0.840 %
#   Shimmer (local)             3.810 %
#   Shimmer (local, dB)         0.350 dB
#   Shimmer (apq11)             3.070 %
#
# and states that because these were derived from noise-influenced MDVP
# measurements, "the correct threshold is probably lower" for the jitter
# measures. That asymmetry has a clinical direction: applying an MDVP
# threshold to a Praat value UNDER-CALLS pathology, because the Praat
# number is systematically smaller on any recording with noise in it.
# Never present a Praat jitter value against an MDVP cutoff without
# saying so. This is a silent failure — the number is plausible, in
# range, and wrong for the comparison being made.
#
# COROLLARY. Do not compare a jitter or shimmer value to a published norm,
# or to a measurement from other software, without naming the program the
# norm came from. Report the variant, the program, and the recording SNR.
#
# ---------------------------------------------------------------------
# THE §7 PLAUSIBILITY BAND DOES NOT CATCH THIS. Jitter 0-5% passed a
# 0.4431% reading that was roughly 60% vibrato.
#
# Provenance: EML PraatGen sandbox, 29 July 2026, Praat 6.6.30

# task spanning 9.84 st, mean F0 244 Hz — local 0.4431%, rap 0.1148%,

## 4. FORMANT ANALYSIS

# ALGORITHM ROUTING (hard):
#
# Choose the formant analysis algorithm based on whether the formant
# ceiling is known:
#
#   CONDITION                             ALGORITHM            SECTION
#   ------------------------------------  -------------------  -------
#   Ceiling uncertain, gender unknown,    FormantPath (burg)   §4A
#     no protocol requirement                                  [DEFAULT]
#
#   Specific ceiling required             Formant (burg)       §4B
#     (replication, protocol, user
#     request)
#
# DEFAULT: FormantPath (burg). This algorithm searches across a range
# of formant ceilings and selects the optimal one per frame. No user
# decision about vocal tract size or gender is needed. This is the
# correct default for any script where the formant ceiling is not
# predetermined by a specific protocol.
#
# OVERRIDE: Formant (burg) with explicit ceiling. Use only when:
#   1. Replicating a published study that used a specific ceiling
#   2. Protocol requires identical ceiling across all participants
#      for between-subject comparability
#   3. User explicitly requests a fixed ceiling
#
# RATIONALE: The previous version of §4 mandated manual ceiling
# selection ("Smaller / Larger" optionmenu) as the universal pattern.
# This forced a Tier 3 decision (estimate a physiological parameter)
# into every formant analysis script, even when the user had no basis
# for making the choice. FormantPath eliminates this friction by
# automating the ceiling search — which is exactly the problem it was
# designed to solve. Per Appendix F's progressive disclosure philosophy,
# parameters that an algorithm can optimize should not be presented to
# the user as mandatory choices.

# FORMANT CEILING SELECTION:

# Recommended GUI pattern:

### 4D. FormantModeler — formant tracking quality assessment

# FormantModeler fits polynomial curves to formant tracks and provides
# goodness-of-fit metrics: R-squared, residual standard deviation,
# outlier detection, track separation. These quantify how reliable the
# formant tracking is — a crucial confidence indicator when reporting
# formant means.
#
# CREATION:
#   selectObject: formantId
#   fmId = To FormantModeler: startTime, endTime, 3, 3
#   # 3 formants, 3rd-order polynomial
#
# KEY METRICS:
#   R-squared (Get coefficient of determination):
#     High (>0.8) = stable, trustworthy tracking
#     Low (<0.5) = unstable — either tracking errors or the polynomial
#     model is wrong for this data (see limitation below)
#
#   Track standard deviation (Get formant standard deviation):
#     Scatter of raw data around the polynomial, in Hz.
#     Large SD = noisy tracking or formant movement.
#
#   Track separation (Get average distance between tracks):
#     Average Hz between adjacent formant tracks. Low separation
#     suggests tracks are merging — a signature of unreliable tracking.
#
#   Invalid data points (Get number of invalid data points):
#     Frames flagged as outliers (>3 SD from polynomial). High counts
#     indicate tracking problems OR a wrong model (see below).
#
# SCOPE LIMITATION (hard):
#
# FormantModeler assumes formants vary smoothly within the analysis
# window. It is VALID for:
#   - Sustained vowels
#   - Single extracted vowel tokens
#   - Sustained singing tones
#
# It is INVALID for:
#   - Connected speech spanning multiple vowels
#   - Vowel sequences with large transitions (e.g., /u i u/)
#   - Any signal where formants change rapidly by design
#
# On connected speech, the polynomial smooths away real formant
# transitions and flags real vowel targets as outliers. Low R-squared
# in this context does NOT mean tracking failed — it means the model
# is wrong for the data. If FormantModeler is needed on connected
# speech, segment by vowel first and apply per segment.
#
# REPORTING:
# When FormantModeler metrics are included in script output, report
# them alongside the formant means as confidence indicators:
#
#   appendInfoLine: "F1 mean: ", fixed$ (meanF1, 0), " Hz",
#       ... " (R-sq = ", fixed$ (rSqF1, 2), ")"
#
# Provenance: Empirical testing on sustained vowels (R-sq > 0.9) and
# connected speech /u i u/ sequence (R-sq < 0.3, all transitions
# flagged as outliers). 21 April 2026.

## 7. PLAUSIBILITY RANGES

# After querying any acoustic measure, check that the result falls within
# plausible bounds. If outside these ranges, emit a non-blocking warning
# via appendInfoLine. Do NOT exitScript — the user may have valid reasons.

# Measure               Plausible range         Warning if outside
# -----------           ---------------         ------------------
# F0 (Hz)               50 – 1000                "F0 value outside typical speech or singing range"
# Jitter (local, %)     0 – 5                   "Jitter unusually high; check voicing"
# Shimmer (local, %)    0 – 15                  "Shimmer unusually high; check voicing"
#   ⚠️ These bands do NOT detect a WRONG-VARIANT reading. A `local` jitter of
#   0.4431% that was roughly 60% vibrato passed this band cleanly. The
#   local/rap ratio is the check that catches it — see §3D.
# HNR (dB)              -20 – 40                "HNR outside expected range"
# Intensity (dB SPL)    20 – 120                "Intensity outside typical recording range"
# CPPS (dB)             0 – 25                  "CPPS outside expected range"
# Formant F1 (Hz)       150 – 1200              "F1 outside typical range"
# Formant F2 (Hz)       500 – 3500              "F2 outside typical range"
# Formant F3 (Hz)       1500 – 4500             "F3 outside typical range"

# GUARD BOTH ENDS OF EVERY BOUNDED RANGE (hard)
#
# A floor-only guard is half a guard. Warn when a measurement approaches
# EITHER limit of any bounded analysis range — pitch floor and ceiling, the
# cepstral peak search range, the derivative low-pass, formant ceiling.
#
# Observed failure: a script warned when minimum F0 came within 10% of the
# pitch floor and had no equivalent at the top. On a real recording the
# measured maximum F0 was 322.87 Hz against a cepstral search ceiling of
# 330 Hz — 98% of the ceiling — and nothing said so. Slightly higher material
# and the measurement degrades with no signal at all.
#
#   if maxF0 > 0.9 * ceiling
#       appendInfoLine: "WARNING: max F0 ", fixed$(maxF0,2),
#           ... " Hz is within 10% of the ", fixed$(ceiling,0),
#           ... " Hz ceiling. Widen the range or treat the result as censored."
#   endif
#
# CHECK THE USER'S STATED RANGE AGAINST THE MEASUREMENT (hard)
#
# When the user supplies an expected range, compare it to what was measured
# and warn on disagreement. The stated value is an INPUT to parameter
# derivation — ceilings are commonly derived as max(600, 1.2 * stated) or
# similar — so a wrong statement propagates silently into every downstream
# parameter.
#
# Observed: user stated F0 stayed below 300 Hz; measurement returned 322.87 Hz;
# nothing flagged it. Report the discrepancy, state which parameters were
# derived from the stated value, and let the user decide whether to re-run.
#
# Pattern for plausibility check:
#
#   if hnr <> undefined
#       if hnr < -20 or hnr > 40
#           appendInfoLine: "WARNING: HNR = ", fixed$ (hnr, 2),
#           ... " dB — outside expected range (-20 to 40 dB)."
#       endif
#   endif

## 10. AVQI PARAMETER SPECIFICATION (Phonanium v02.06)

# ----------------------------------------------------------------------------
# 10A. INPUT REQUIREMENTS
# ----------------------------------------------------------------------------
#
# AVQI requires TWO recordings per speaker:
#   1. Sustained vowel (named "sv") — /a/ phonation
#   2. Continuous speech (named "cs") — connected speech sample
#
# The script concatenates voiced portions of both into a single analysis
# signal ("avqi") before computing acoustic measures.
#
# Sustained vowel handling:
#   - If duration > 3 seconds, extracts the LAST 3 seconds
#   - If duration <= 3 seconds, uses the entire recording
#
# Continuous speech handling:
#   - Silence detection: To TextGrid (silences): 50, 0.003, -25, 0.1, 0.1,
#     "silence", "sounding"
#   - Voiced segment extraction via power thresholding (30% of global power)
#     and zero-crossing rate filtering (< 3000 crossings/s)
#   - 30 ms sliding window for voiced/unvoiced classification
#   - Voiced segments concatenated into a single signal

# ----------------------------------------------------------------------------
# 10B. HIGH-PASS FILTER (applied to BOTH recordings before analysis)
# ----------------------------------------------------------------------------

# Filter (stop Hann band): 0, 34, 0.1
#
#   from frequency = 0 Hz
#   to frequency = 34 Hz
#   smoothing = 0.1 Hz
#
# This removes subsonic noise and DC offset. Applied to BOTH cs and sv
# BEFORE any analysis. This filter is NOT used in standard clinical
# analysis (Appendix D §§1–6) — it is AVQI-specific.

# ----------------------------------------------------------------------------
# 10C. CPPS (Smoothed Cepstral Peak Prominence)
# ----------------------------------------------------------------------------

# To PowerCepstrogram: 60, 0.002, 5000, 50
#
#   pitch floor = 60 Hz        (same as clinical)
#   time step = 0.002 s        (same as clinical)
#   maximum frequency = 5000 Hz (same as clinical)
#   pre-emphasis from = 50 Hz  (same as clinical)

# Get CPPS: "no", 0.01, 0.001, 60, 330, 0.05, "parabolic", 0.001, 0, "Straight", "Robust"
#
#   subtract tilt before smoothing = "no"
#   time averaging window = 0.01 s
#   quefrency averaging window = 0.001 s
#   pitch floor = 60 Hz
#   pitch ceiling = 330 Hz
#   tolerance = 0.05
#   interpolation = "parabolic"
#   tilt line quefrency range floor = 0.001
#   tilt line quefrency range ceiling = 0
#   line type = "Straight"
#   fit method = "Robust"
#
# All CPPS parameters are IDENTICAL to the clinical defaults in §5B.
# No AVQI-specific CPPS deviations exist. (Corrected 21 April 2026.)

# ----------------------------------------------------------------------------
# 10D. LTAS SLOPE
# ----------------------------------------------------------------------------

# To Ltas: 1
#
#   bandwidth = 1 Hz

# Get slope: 0, 1000, 1000, 10000, "energy"
#
#   from frequency = 0 Hz
#   to frequency = 1000 Hz
#   from frequency 2 = 1000 Hz
#   to frequency 2 = 10000 Hz
#   averaging method = "energy"
#
# Measures the slope between the 0–1000 Hz and 1000–10000 Hz bands.

# ----------------------------------------------------------------------------

# Compute trend line: 1, 10000
#
#   from frequency = 1 Hz
#   to frequency = 10000 Hz

# Get slope: 0, 1000, 1000, 10000, "energy"
#
# Same query as 10D but applied to the trend line Ltas object.

# ----------------------------------------------------------------------------
# 10F. SHIMMER
# ----------------------------------------------------------------------------

# To PointProcess (periodic, cc): 50, 400
#
#   pitch floor = 50 Hz
#   pitch ceiling = 400 Hz

# Sound + PointProcess selected together:

# Get shimmer (local): 0, 0, 0.0001, 0.02, 1.3, 1.6
#
#   from time = 0 (all)
#   to time = 0 (all)
#   shortest period = 0.0001 s
#   longest period = 0.02 s
#   maximum period factor = 1.3
#   maximum amplitude factor = 1.6
#
# UNIT CONVERSION: The raw return value is a proportion (0–1).
# AVQI multiplies by 100 to get percentage:
#   shim = percentShimmer * 100

# Get shimmer (local_dB): 0, 0, 0.0001, 0.02, 1.3, 1.6
#

# ----------------------------------------------------------------------------
# 10G. HNR (Harmonics-to-Noise Ratio)
# ----------------------------------------------------------------------------

# AVQI uses Voice report to extract HNR, NOT To Harmonicity (cc) directly.
# This is a KEY DIFFERENCE from the clinical approach in Appendix D §4.

# To Pitch (cc): 0, 75, 15, "no", 0.03, 0.45, 0.01, 0.35, 0.14, 600
#
# NOTE: This is the old-syntax equivalent of:
# To Pitch (raw cross-correlation): 0, 75, 600, 15, "no", 0.03, 0.45, 0.01, 0.35, 0.14
#
#   time step = 0 (auto)
#   pitch floor = 75 Hz
#   pitch ceiling = 600 Hz
#   max candidates = 15
#   very accurate = "no"
#   silence threshold = 0.03
#   voicing threshold = 0.45
#   octave cost = 0.01
#   octave jump cost = 0.35
#   voiced unvoiced cost = 0.14

# Sound + Pitch → To PointProcess (cc)
# Sound + Pitch + PointProcess → Voice report: 0, 0, 75, 600, 1.3, 1.6, 0.03, 0.45
#
#   from time = 0 (all)
#   to time = 0 (all)
#   pitch floor = 75 Hz
#   pitch ceiling = 600 Hz
#   maximum period factor = 1.3
#   maximum amplitude factor = 1.6
#   silence threshold = 0.03
#   voicing threshold = 0.45
#
# HNR extracted by string parsing:
#   hnr = extractNumber (voiceReport$, "Mean harmonics-to-noise ratio: ")

# ----------------------------------------------------------------------------
# 10H. AVQI REGRESSION FORMULA (v02.06)
# ----------------------------------------------------------------------------

# avqi = ((3.295 - (0.111 * cpps) - (0.073 * hnr) - (0.213 * shim)
#          + (2.789 * shdb) - (0.032 * slope) + (0.077 * tilt)) * 2.208) + 1.797
#

#   cpps  = Smoothed Cepstral Peak Prominence (dB) — Section 10C
#   hnr   = Mean Harmonics-to-Noise Ratio (dB) — Section 10G
#   shim  = Shimmer local (%) — Section 10F (raw × 100)
#   shdb  = Shimmer local dB (dB) — Section 10F
#   slope = LTAS slope (dB) — Section 10D
#   tilt  = LTAS trendline tilt (dB) — Section 10E
#
# AVQI score range: approximately 0–10
# Higher = more dysphonic
# Threshold for dysphonia: user-configurable (stored in thresholdAVQI.Table)

# Citation:
#   Maryn, Y., De Bodt, M., Barsties, B., & Roy, N. (2014).
