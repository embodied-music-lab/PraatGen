# Source: Praat manual — Text styles, Special symbols

#
# CRITICAL: These characters have special meaning in Praat's Picture window
# text renderer. Using them bare in Text:, Text left:, Text bottom:,
# Text top:, or One mark: commands will produce unintended formatting
# instead of the literal character.
#
# Commas and double quotes in text written to a CSV file (file names,
# labels), and the encoding of text written to a file, are in SECTION 8.
#
# Version: 1.1
# Date: 27 November 2026

# ============================================================================
# SECTION 1: STYLE TOGGLE CHARACTERS
# ============================================================================
#
# These characters toggle text styles when they appear in drawing text.
# They affect the NEXT character (single) or all characters UNTIL the
# closing toggle (double).
#
# Character   Effect (single)           Effect (double)
# ---------   ----------------------    ---------------------------
# %           Next letter italic        %%...% = italic range
# #           Next letter bold          ##...# = bold range
# ^           Next letter superscript   ^^...^ = superscript range
# _           Next letter subscript     __..._ = subscript range
#
# To display the LITERAL character, use the backslash escape:
#
# Desired     Escape sequence (backslash + char + SPACE)
# -------     ------------------------------------------
# %           \%                (NOTE: trailing space is part of the escape)
# #           \#                (NOTE: trailing space is part of the escape)
# ^           \^                (NOTE: trailing space is part of the escape)
# _           \_                (NOTE: trailing space is part of the escape)
#
# The trailing space after the backslash trigraph is consumed by the
# renderer — it does not appear in the output.

# ============================================================================
# SECTION 2: COMMON AXIS LABEL PATTERNS
# ============================================================================
#
# WRONG: "Percentage (%)"       → renders as "Percentage ()" with invisible italic toggle
# RIGHT: "Percentage (\% )"     → renders as "Percentage (%)"
#
# WRONG: "F0 (Hz)"              → The "0" after F becomes subscript!
#                                  Actually safe here because _ not present,
#                                  but "F_0" would trigger subscript.
# SAFER: "F0 (Hz)" is fine as-is — only _ triggers subscript
#
# WRONG: "F#1 (Hz)"             → "1" becomes bold
# RIGHT: "F\# 1 (Hz)"          → literal "F#1 (Hz)"
#
# WRONG: "x^2"                  → "2" becomes superscript (may be desired!)
# RIGHT: "x\^ 2"               → literal "x^2" if superscript NOT desired

# ============================================================================
# SECTION 3: SAFE LABEL CONSTRUCTION PATTERN
# ============================================================================
#
# For programmatic label construction, sanitize ALL display strings:
#
#   # Escape special characters for Praat text rendering
#   safeLabel$ = replace$ (rawLabel$, "%", "\% ", 0)
#   safeLabel$ = replace$ (safeLabel$, "#", "\# ", 0)
#   safeLabel$ = replace$ (safeLabel$, "^", "\^ ", 0)
#   safeLabel$ = replace$ (safeLabel$, "_", "\_ ", 0)
#
# IMPORTANT: The replacement strings include a trailing space.
# This is correct — the space is consumed by the renderer.
#
# Apply this sanitization to:
#   - Column names used as axis labels
#   - User-provided title strings
#   - Any text derived from data (e.g., category labels from Table columns)
#
# Do NOT apply to intentionally formatted text where you WANT the style toggle
# (e.g., italic variable names in figure titles).

# ============================================================================
# SECTION 4: SMALL TEXT
# ============================================================================
#
# \s{...} renders enclosed text in a smaller font size.
# Example: "W\s{ARP}" renders as W with small "ARP"
# This is useful for acronyms in titles.

# ============================================================================
# SECTION 5: SUBSCRIPT / SUPERSCRIPT IN LABELS (intentional use)
# ============================================================================
#
# When you WANT subscripts or superscripts:
#   "%F_0" renders as italic F with subscript 0 (standard F0 notation)
#   "%m%c^^2^" renders as italic m, italic c, superscript 2
#
# When labeling formants:
#   "F_1" = F with subscript 1 (publication style)
#   "F1"  = plain F1 (acceptable for screen display)

# ============================================================================
# SECTION 6: OTHER BACKSLASH TRIGRAPHS
# ============================================================================
#
# Praat supports ~100 backslash trigraphs for accented characters,
# Greek letters, phonetic symbols, and mathematical symbols.
# Full list: https://www.fon.hum.uva.nl/praat/manual/Special_symbols.html
#
# Common ones for voice science:
#   \al = α (alpha)
#   \be = β (beta)
#   \ga = γ (gamma)
#   \de = δ (delta)
#   \ep = ε (epsilon)
#   \si = σ (sigma)
#   \mu = μ (mu)
#   \pi = π (pi)
#   \ct = ɔ (open-o / turned c)
#   \sw = ə (schwa)
#   \ae = æ (ash)
#   \ic = ɪ (small capital I)
#   \hs = ʃ (esh)

# ============================================================================
# SECTION 8: TEXT WRITTEN TO A CSV FILE
# ============================================================================
#
# The rules are Rule 27, "CSV text fields" and "File text encoding", in
# PRAATGEN_RULES_FULL.md: every text field in double quotes, each quote
# inside it doubled, and Text writing preferences: "UTF-8" before the first
# write. In a Praat string literal a double quote is written as two double
# quotes, so """" is a one-character string (code 34).
#
# How Praat handles the same text:
#
#   writeFileLine: / appendFileLine:
#       Write the string exactly as built, with no quoting. The script
#       does the quoting.
#
#   Save as comma-separated file
#       Quotes a cell only when it holds a comma, and never doubles a quote.
#       say "hi" is written bare; a, "b" is written "a, "b"", which
#       Python's csv module reads as a, b"". Write text fields with the
#       Rule 27 pattern. Use this save only for a table with no text
#       cells (numbers only).
#
#   Read Table from comma-separated file
#       Keeps a quoted comma in its cell, and deletes every double quote
#       from every cell, doubled or not: "say ""hi""" reads as say hi.
#       A double quote in a file name or label can't survive Praat's own
#       CSV reader, however the file was written.
#
#   Save as tab-separated file
#       Writes each cell with no quoting. A cell holding a tab stops the
#       save with an error that names the row ("contains a separating tab
#       inside a cell"). Praat's tab reader reads quotes back as written. Python's csv module, reading with a
#       tab delimiter, drops the quotes from a cell that starts with one:
#       "take 2" Smith.wav reads as take 2 Smith.wav.
#
#   File names
#       Smith, Jo.wav survives Create Strings as file list and Read from
#       file, and the Sound is named Smith__Jo. Take the file name for a
#       CSV column from the file list (Get string:), not from the object
#       name. Non-ASCII names (chantée_ü.wav, a—b.wav, 歌.wav) come back
#       from the file list exactly, and Read from file opens them.
#
# Text encoding (writeFileLine:, appendFileLine:, Save as comma-separated
# file, Save as tab-separated file):
#
#   Default setting
#       The whole file is written as UTF-16 big-endian with a BOM (fe ff) as
#       soon as one character in it is non-ASCII. An all-ASCII file stays
#       ASCII. --utf8 on the command line doesn't change this.
#
#   Text writing preferences: "UTF-8"
#       The same commands write UTF-8 with no BOM. "UTF-16" and
#       "try ASCII, then UTF-16" both write UTF-16 with a BOM. Praat keeps
#       the setting in its preferences file between runs, so the script
#       sets it itself, every time, before its first write.
#
#   Reading back
#       Python's csv module reads the names exactly only with the matching
#       codec: utf-16 for the default output, utf-8 after the setting. The
#       wrong codec raises an error. Praat's comma- and tab-separated
#       readers read both encodings exactly, with no setting.
#
#   String literals
#       String literals written to a file stay pure ASCII whatever the
#       setting (Rule 24C).
#
# Provenance: sandbox-verified 6.6.30, 27 Nov 2026: each behavior above was
# run and the output files read byte by byte; Python's csv module read the
# Rule 27 pattern's output exactly.
