# ====================================
# Source: github.com/praat/praat C++ source
#   Command names: praat_addAction/praat_addMenuCommand registration strings
#   Parameters: FORM block parsing, joined to registrations via callback name
# Version: 6.4.62 (March 13, 2026)
# Extraction date: 2026-04-08
#
#   version 3 — 8 April 2026
#
# ⚠️ VERSION PIN AND COMPLETENESS BANNER (read before using as a fallback)
#
#   This catalogue was extracted from Praat 6.4.62. Other PKB files have
#   since been verified against later builds (6.4.65, 6.4.67, 6.6.30).
#   Where they disagree, the object-specific COMMANDS_*.txt file governs —
#   it carries the newer sandbox verification stamp.
#
#   ⚠️ EXTRACTION GAPS — MEASURED, AND CORRECTED WHERE VERIFIED
#
#   The extractor DROPS paired range fields. Praat renders a range as two
#   boxes on one row using the `left Xxx` / `right Xxx` label idiom (see
#   APPENDIX_C_GUI.txt §C.1, "Side-by-side fields"). The extraction counted
#   those as one field, or as none. String-array fields (`...$#`) are dropped
#   the same way. Affected commands are therefore documented with FEWER
#   parameters than they take.
#
#   Measured rate: 22 defects in 542 commands probed across 8 object types
#   (4.1%). Projected ~100 more of the same class in the object types that
#   have no COMMANDS_*.txt file.
#
#   CORRECTIONS APPLIED TO THIS FILE (verified by execution before editing):
#     30 Jul 2026  Spectrogram: Paint  8 -> 10  (leading time-range pair)
#
#   Entries marked "# CORRECTED <date>" are hand-verified against a live
#   Praat and are no longer extraction output. Everything else in this file
#   is the 6.4.62 extraction as produced.
#
#   Confirmed examples still uncorrected (catalogue arity vs live 6.6.30):
#     Harmonicity  Draw                 catalogue 0  actual 4  (from/to time, min, max)
#     Harmonicity  Get mean             catalogue 0  actual 2  (from/to time)
#     Harmonicity  Get standard deviation catalogue 0 actual 2
#     Intensity    Draw                 catalogue 3  actual 5
#     Intensity    Get quantile         catalogue 1  actual 3
#     Intensity    Get standard deviation catalogue 0 actual 2
#     Pitch        Draw/Speckle × erb, mel, semitones(100/200/440)
#                                       catalogue 3  actual 5  (10 commands)
#     PointProcess Draw                 catalogue 1  actual 3
#     TextGrid     Draw                 catalogue 3  actual 5
#     TextGrid     Merge                catalogue 0  actual 1
#     Sound        To Covariance (channels)  catalogue 0  actual 2
#     Sound        To CrossCorrelationTable  catalogue 1  actual 3
#     Sound        To Polygon                catalogue 4  actual 6
#
#   WHERE THIS MATTERS. 22 of the 136 object types have a curated
#   COMMANDS_*.txt, and those files carry the CORRECT arity — they were
#   hand-verified and this sweep confirmed them. **If a command is in a
#   curated COMMANDS file, use that file and do not consult this one.** The
#   remaining 114 types (2,464 commands: KlattGrid, Matrix, TableOfReal, DTW,
#   Discriminant, FormantModeler, EEG, OTGrammar, …) have no curated file, so
#   this catalogue is the sole authority — which is exactly the fallback case
#   it exists to serve, and the only place these gaps can bite.
#
#   HOW TO USE IT SAFELY. Before emitting a catalogue-sourced command that
#   plausibly takes a time, frequency, quefrency or value RANGE, verify the
#   real arity — either in the sandbox (call it with excess arguments; Praat
#   replies "Command requires only N arguments") or against the dialog. Do
#   not trust a catalogue parameter list that lacks an obvious range pair.
#
#   This catalogue is NOT exhaustive. Other known gaps:
#     - Some object types appear only in the §1 class hierarchy and expose
#       no commands in §2. Electroglottogram is the clear case: the tree
#       line "Electroglottogram -> Sound -> Vector -> Matrix" is present,
#       but the command dispatcher exposes no actions here. See
#       COMMANDS_Electroglottogram.txt.
#     - Some query commands are under-specified relative to the COMMANDS
#       files: the from-time/to-time fields on `Get mean`, `Get minimum`,
#       and `Get quantile` are omitted in the Formant and Pitch blocks but
#       correctly documented in COMMANDS_Formant.txt and COMMANDS_Pitch.txt.
#     - STRING-ARRAY fields (`...$#`) are dropped the same way paired ranges
#       are. `Table: Bar plot` is the confirmed case: the catalogue lists 8
#       parameters with neither `vertical columns$#` nor `colours$#`; the
#       real command takes 10. See COMMANDS_Table.txt.
#
#   NOT VERSION DRIFT. Where a COMMANDS file and this catalogue disagree on
#   arity, the cause so far has always been the extraction, not a change in
#   Praat. Both confirmed cases — `Formant: Formula` (5 parameters) and
#   `Table: Bar plot` (10) — were executed against 6.4.62 AND 6.6.30 on
#   29 July 2026 and are identical in both. Praat command signatures are
#   stable; assume an extraction gap before assuming a signature change.
#
#   Therefore: a command or object NOT FOUND here is not proof of absence.
#   An empty or missing result for a type that has its own COMMANDS file
#   means "check the COMMANDS file," not "the capability does not exist."
#
# Command names in §2 are SCRIPTING names — the exact strings that
# Praat's interpreter matches when reading a script. These come from
# the registration layer (praat_addAction calls), NOT from FORM dialog
# titles. FORM dialog titles can differ (e.g., "To Formant (Burg method)"
# in the dialog vs "To Formant (burg)" in scripts).

# Parameter defaults are Praat SOURCE CODE defaults — the values Praat
# uses when no argument is supplied. These may differ from clinical
# best-practice values in APPENDIX_D_CLINICAL_DEFAULTS.txt.

################################################################################
# §1 CLASS HIERARCHY
# Key object types and their inheritance chains.
# Critical insight: Sound IS a Matrix, so Formula: operates on it at C speed.
################################################################################

# Core analysis chain
Sound -> Vector -> Matrix -> SampledXY -> Sampled -> Function -> Daata -> Thing
LongSound -> SampledXY (direct file-backed, not Matrix)
Pitch -> Sampled -> Function
Formant -> Sampled -> Function
Intensity -> Vector -> Matrix
Spectrum -> Matrix
Spectrogram -> Matrix
Harmonicity -> Vector -> Matrix
PointProcess -> Function
TextGrid -> Function
Table -> Daata (NOT Matrix — row/column, not sampled)
TableOfReal -> Daata

# Spectral/cepstral
PowerCepstrogram -> Matrix
PowerCepstrum -> Cepstrum -> Matrix
Ltas -> Vector -> Matrix
Cochleagram -> Matrix

# Tiers (all inherit time-point structure)
PitchTier -> RealTier -> AnyTier -> Function
IntensityTier -> RealTier
DurationTier -> RealTier
AmplitudeTier -> RealTier
FormantGrid -> Function (contains multiple RealTier tracks)

# Synthesis
Manipulation -> Function (contains PitchTier + DurationTier + Sound)
KlattGrid -> Function

# Statistics (David Weenink)
PCA -> Eigen -> Daata
Discriminant -> Daata
Configuration -> TableOfReal
Dissimilarity -> Proximity -> TableOfReal
MixingMatrix -> TableOfReal

# Special
Electroglottogram -> Sound -> Vector -> Matrix
PatternList -> Matrix (neural net input)
ActivationList -> Matrix (neural net output)
DTW -> Matrix

#   fields on several interval-query commands. Affected blocks include
#   Formant `Get mean`, `Get minimum`, `Get maximum`, `Get quantile`,
#   `Get standard deviation` and the corresponding Pitch queries: each
#   actually takes a time range (commonly "Time range (s) = 0.0" to
#   "0.0 (= all)") in addition to the fields listed here.
#
#   Writing one of these calls from the arity shown below will drop the
#   time-range arguments and produce a runtime error or a whole-object
#   measurement where an interval was intended. COMMANDS_Formant.txt and
#   COMMANDS_Pitch.txt carry the correct, sandbox-verified signatures —
#   use them for any query command that has a COMMANDS file entry.
